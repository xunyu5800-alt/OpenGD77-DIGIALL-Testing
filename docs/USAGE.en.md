## 1. Hardware and package selection

Use only the supported **dual-band MD-UV380/MD-UV390** family, not single-band MD-380/MD-390.

| Hardware | Package identifier | Backlight / PA |
| --- | --- | --- |
| Ordinary 5W + GPS, the confirmed test radio | `MD_UV380_UV390_5W_GPS` | PD8 / PC6 |
| Confirmed Plus 10W PD8 board | `PLUS_10W_PD8_GPS` | PD8 / PC6 |
| Confirmed Plus 10W PC6 board | `PLUS_10W_PC6_GPS` | PC6 / PD8 |

Identify the actual 10W board. All three builds enable main-screen C4FM DN RX/TX and GPS. Both 10W profiles need radio testing. GPS requires installed hardware.

If PTT reports Receive Only, check Channel Details → RX Only and confirm the version and board profile of the installed Stage 03. The rc.8 10W images enabled C4FM reception only.

## 2. Installation and upgrades

1. Back up the codeplug, **this radio's calibration**, and important records in CPS. Keep a working original firmware and recovery method.
2. Download the matching hardware ZIP from the Release, check `SHA256SUMS.txt`, extract it and read its `INSTALL`.
3. **Current project font/pinyin installed: flash matching `03` only.** First install or R250326 resources: use the same hardware/version's `01 font → 02 pinyin → 03 main`.
4. Boot each resource writer normally; wait for `COMPLETE - VERIFIED` and screen-off, then power off before the next stage. Stop on failure and check package selection.
5. Main firmware uses the CPS Firmware Loader/codec merge procedure. Public packages have no proprietary AMBE/donor. Obtain and use it only with applicable rights; do not redistribute merged firmware.
6. After first resource installation, SK1+5 at power-on checks for `CJK data OK / log reset`. Resources occupy the last512KiB of external Flash; back up needed records and do not mix old-format resources.

Upgrading does not automatically correct a local calibration generated by a previously incorrect10W build. Do not import another radio's calibration. Consult the [5W installation/calibration guide (Chinese)](MD_UV380_5W_GPS.zh-CN.md); its old filenames are historical, current Release names take precedence. Resource details are in the [Chinese-language installation reference](CHINESE_INPUT.zh-CN.md); current operation follows this guide and the Release.

## 3. Common controls and DMR

| Control | Action |
| --- | --- |
| SK2 + short `*` | FM → DMR → C4FM → FM |
| Physical PTT | Transmit where mode/channel/context permit; release to stop |
| SK2 + front UP/DOWN | Adjust shared power settings/calibration; displayed watts are not RF measurements |
| Front UP/DOWN during DMR reception | Step through the RX group's TGs and discard the previous group's queued audio |
| DMR hold SK1 | Save ALL/current-TG destination-filter selection |
| DMR short SK1 or hold `0` | Finder search; GREEN locks TG/CC/TS, RED restores entry settings |
| DMR orange quick menu | Includes TGL RX-group-list filtering |
| Hold GREEN on digital main screen | Remote position/distance/compass; RED returns |

TG means selected destination, TGL the RX list, ALL all destinations; CC/TS retain independent filtering. `RX TG91 [ALL]` identifies the actual call while `TX TG:9` remains the selected transmit destination. Receiving another group does not automatically change TX. [DMR filtering/group controls](DMR_LIVE_TG_FIX.en.md)

### Setting the radio date and time

Open **Menu → Radio info** and use the front UP/DOWN keys to find Date or Time. Enter eight digits for the date (`YYYYMMDD`) or six for the time (`HHMMSS`), then press GREEN to save each value.

For local time, set your offset under **Options → Display options → Timezone**, then set **Time** to **Local**. Selecting UTC shows UTC on both the home screen and Radio info.

Saving a manual date or time switches off GPS clock sync while GPS positioning remains available. To resume automatic sync, turn on **Options → General options → GPS Clock Sync** and press GREEN to save.

## 4. Everyday C4FM (ordinary5W)

Use main-screen PTT; the `4:MIC` diagnostic panel is not required. RX defaults to RAM. Front UP/DOWN selects DG-ID0–127; short `*` opens direct DG entry, GREEN confirms and RED cancels. Short SK1 temporarily searches all DGs; hold SK1 saves ALL/selected filtering. SK2+UP/DOWN uses the DMR power ladder.

- **Settings:** SK2+GREEN or hold `*` opens shared channel details. Knob selects a field, front UP/DOWN changes it, GREEN saves, RED cancels. C4FM DG/filter/independent TX trim appear here; CC/TS are DMR-only.
- **Rooms:** short `#` or SK2+`#` opens the page without transmitting. `#` queries; five digits then GREEN connects; hold `*` disconnects. Connection is verified only by an accepted reply, not a timeout.
- **Diagnostics:** SK1+short`#` cycles main/RX/health pages. Diagnostic GREEN switches RAM/I2S;7/9 adjust playback gain. RAM is the preferred tested RX path.
- **Timeout:** main PTT uses channel TOT, falling back to60s when zero. Advanced diagnostics have separate limits. Releasing PTT completes a bounded ending; faults stop transmission.

Split-frequency example: hotspot **RX433.950MHz/TX439.950MHz** requires radio **RX439.950MHz/TX433.950MHz**. SDR recording centre and radio TX frequency are separate settings.

The current5W test baseline is D22/INV/G4/N2/E1, not a universal calibration. Hotspot RXOffset affects multiple modes: keep its DMR-working value and adjust only the radio's independent C4FM TX trim if needed. Trim defaults0 and does not change FM/DMR or factory calibration. [Full C4FM guide](C4FM_OPERATING.en.md)

### YSF2DMR bridging

In Pi-Star enable YSF/YSF2DMR and apply, then configure the Yaesu System Fusion section with your valid DMR ID, target master, Hotspot Security and TG. Select **00002/Link YSF2DMR** as startup host. Keep credentials on the hotspot, out of public screenshots/logs.

**DG-ID0 is not a DMR TG.** The bridge selects the TG; a five-digit YSF room is not a six-digit TG. Do not connect another reflector through the room page during a local-YSF2DMR test. Verify delivery using an independent receiver/Hoseline; local tail echo is not proof of target-TG delivery. [Bridge troubleshooting](C4FM_NETWORK_ECHO.en.md)

## 5. GPS, APRS and position pins

For a live APRS location beacon, select **Options → APRS → Location → GPS** and wait for a valid fix. Use **Location → Channel** for the CPS fixed position, or the radio's saved position if no CPS coordinates are configured. Set CPS position ambiguity to zero when comparing transmitted coordinates with the radio's GPS. APRS uses WGS84 by default. [APRS Protocol Reference](https://www.aprs.org/doc/APRS101.PDF)

GPS defaults on for new installs; a subsequently saved manual OFF is retained. Check satellites/fix in the GPS menu: enabled hardware is not a valid fix. GPS Flash track logging is separate and remains disabled.

APRS decodes audio from the **current FM frequency** in the background. Tune the local permitted APRS frequency; one receiver cannot simultaneously monitor APRS while receiving DMR/C4FM or another frequency. Power saving, recording and competing audio features can affect reception. [GPS/APRS detailed limits (Chinese)](GPS_APRS.zh-CN.md)

- A valid APRS position opens its card automatically when context permits. It closes after five seconds and returns to the previous screen. Open a card manually with GREEN from the log to keep it open. LEFT/RIGHT changes position/text, and RED returns.
- The APRS log retains up to 16 entries across power cycles. At capacity, new packets replace the oldest unstarred entry. Hold SK2 and tap `#` to toggle the selected entry's favorite marker (`*`). Tapping `#` alone clears unstarred entries.
- A **pin** means valid remote coordinates have been received, independent of local GPS and without a freshness guarantee. It appears on new DMR/C4FM caller screens, DMR Last Heard and APRS rows.
- Digital calls retain the main screen; hold GREEN for position. Select a pinned Last Heard caller and hold GREEN for a historical `LAST` position; short GREEN still selects the group.
- Remote coordinates remain visible without a local reference. Valid live local GPS, otherwise saved position, enables distance/initial bearing/north-up compass. The arrow is not a magnetic handset heading. [Position guide/images](RECEIVED_POSITION.en.md)

## 6. Chinese input, scanning, recording and extras

| Feature | Controls and limits |
| --- | --- |
| Chinese input | In supported name editors SK2+`#` enters/exits pinyin. Multi-tap digits enter letters (v for ü), LEFT/RIGHT selects a character, UP/DOWN pages, GREEN inserts, RED deletes. Exit pinyin and use the editor's normal save.16-byte names hold up to8 Han characters; protocol fields do not all support Chinese. |
| Waterfall | FM VFO hold`#` opens; RED exits. Short`*` toggles signal dwell, hold`*` switches FAST80/FINE160 points. It scans sequential RSSI with one receiver, not simultaneous wideband sampling. |
| RX recording | Use Logs/RX Recorder. Current recording supports FM, not promised DMR/C4FM recording. Observe overflow/I/O notices; abrupt power loss may lose the active recording. |
| Five-tone/Morse | Existing menus/logs remain; configure in their pages and consider competing audio ownership. |

## 7. Reporting and recovery

Report actual hardware/board, full ZIP name, mode, reproducible steps and relevant counters. BER reports need equipment and conditions; power labels are not measurements. Remove passwords, private precise positions, others' recordings and unnecessary personal details before sharing. If backlight fails, check for text with a torch and verify the profile; recover using your saved working firmware/procedure rather than blindly clearing calibration.
